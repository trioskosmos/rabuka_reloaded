# Plan: Improve QA Test Assertions and Coverage

## Goal
Identify weak assertions in existing QA tests and improve test coverage to ensure robust validation of game behavior.

## Current State Analysis

### Strengths
- Good core mechanic coverage (baton touch, member playing, live performance)
- Many tests verify specific numerical values
- Effective edge case testing in recent additions
- Strong verification patterns in `qa_new_tests*.rs` and `untested_abilities_test.rs`

### Weaknesses Identified
1. **Weak assertions in `qa_test_suite.rs`**:
   - Many tests verify zone count changes but not specific card movements
   - Some energy checks use range assertions instead of exact values
   - Limited intermediate state verification in multi-step tests
   - Over-reliance on negative assertions without positive verification

2. **Incomplete QA coverage**:
   - Multiple entries in `qa_card_list.md` have missing/incomplete test status
   - Some shared ability entries may lack variant-specific verification
   - Gaps between QA IDs in data file and those covered in test suite

3. **Test specificity improvements needed**:
   - Card movement tests often don't verify exact source/destination
   - Modifier tests may not check exact values for all affected cards
   - Choice tests sometimes don't verify exact choice options

### 3. Improve Test Specificity Patterns

**Across all test modules**, implement these improvements:

**Card Movement Verification**:
- Instead of: `assert!(game.state.player1.waitroom.cards.contains(&card_id))`
- Use: `assert_eq!(game.state.player1.waitroom.cards[0], expected_card_id, "...")`  
- And: `assert!(!game.state.player1.waitroom.cards.contains(&unexpected_card_id), "...")`

**Energy Verification**:
- Instead of: `assert!(final_energy_active <= initial_energy_active)`
- Use: `assert_eq!(final_energy_active, expected_value, "...")` when exact value known

**Modifier Verification**:
- Check exact values for all affected cards, not just existence
- Verify absence of modifiers on unaffected cards

**Choice Scenario Testing**:
- Verify exact choice options presented
- Test all choice branches when applicable
- Verify correct outcomes for each choice path

### 4. Add Missing Edge Case Tests

**Where appropriate**, add tests for:
- Boundary conditions (min/max values)
- Empty/null state handling
- Invalid input/error conditions
- Timing sensitivities
- Resource exhaustion scenarios
