# Plan: Identify Generic Rule Gaps in qa_data.json

## Goal
Audit `cards/qa_data.json` from highest IDs downward, surface generic (non-card-specific) questions not represented in the engine code, and propose implementation work.

---

## High-numbered generic questions most likely missing from code

### 1. Q115 — Heart modifier application order (set before additive)
- **Date:** 2025.06.06
- **Rule:** When both a "set required hearts to X" and an "increase/decrease required hearts by Y" effect apply to the same live, set takes priority and additive is applied on top.
- **Current evidence of support:** `engine/src/ability/effects/score.rs:172` (`execute_modify_required_hearts`) applies set vs additive, but order between simultaneous modifiers on a single live card is not obviously enforced. `engine/src/turn/live.rs:242` builds `required_arr` by checking `has_set` first, but multi-modifier layering logic should be verified.
- **Gap:** No `test_q115` in `engine/src/qa_test_suite.rs`; no dedicated test file found for this ordering rule.
- **Impact:** High — affects live difficulty calculation for combo cards.

### 2. Q104 — Look/top-deck when deck size equals look count
- **Date:** 2025.05.30
- **Rule:** Revealing N cards when the deck has exactly N cards does **not** trigger a refresh (because the cards never left the deck). Refresh only happens when all revealed cards are moved to discard.
- **Current evidence of support:** `look.rs:641` `reveal_until` refreshes only after `draw()` returns `None`. The deck-size-equals-N path likely works correctly because `draw()` cards are held in `gs.revealed_cards` without refresh; but no automated test covers this boundary.
- **Gap:** No test in `qa_test_suite.rs`; no dedicated edge-case test for "deck size == look count, no refresh".
- **Impact:** Medium — affects deterministic top-deck look abilities.

### 3. Q101/Q102/Q100 — Partial refresh during cheer when deck and discard both empty
- **Date:** 2025.05.21
- **Rule:** During cheer, if the deck empties and the discard is also empty, cheer terminates gracefully. Looked-at cards already revealed are NOT included in the refresh set.
- **Current evidence of support:** `reveal_until:669-690` handles `refresh_count == 0` by breaking. The "revealed cards excluded from refresh" rule is probably implicit in the code structure but **not tested**.
- **Gap:** No tests in `qa_test_suite.rs`; `heart_override_test.rs` exists but doesn't cover deck-empty cheer termination.
- **Impact:** Medium — edge case but rule clarifies behavior when all zones are empty.

### 4. Q86 — Look at N cards when deck size < N (refresh mid-look)
- **Date:** 2025.03.17
- **Rule:** When deck has fewer cards than the look count, refresh occurs mid-look, and the revealed cards are **not** part of the refresh pool.
- **Current evidence of support:** `look.rs:641` handles refresh in the loop; the "original revealed cards excluded from refresh" is structurally plausible.
- **Gap:** No direct automated test.
- **Impact:** Medium — affects top-deck search abilities.

### 5. Q141–Q138 — Energy-under-member systemic rules
- **Date:** 2025.07.22
- **Rules:**
  - Q141: Member under energy + baton touch → energy returns to energy deck, new member enters with no energy underneath.
  - Q140: Member under energy leaving stage/hand → only member card moves, energy returns to energy deck.
  - Q139: Member under energy changing areas → energy travels with the member.
  - Q138: Energy under member **cannot** be used to pay costs.
- **Current evidence of support:** Some card-specific tests exist (e.g., `b7_constant_ability_test.rs` touches member-under-energy cost logic), but the **systemic** propagation rules (travel on area move, return on zone change, exclusion from cost payment) have no dedicated generic tests.
- **Gap:** No generic test file for "energy under member" mechanics.
- **Impact:** High — affects any card placing energy under members.

### 6. Q72/Q70/Q71 — Area occupation / same-turn placement rules
- **Date:** 2025.02.10
- **Rules:**
  - Q70: Once a member occupies an area this turn, no other member can enter that area (even via effect).
  - Q71: After the occupying member leaves the area, another member may enter the same turn.
  - Q72: Live card set phase has no restriction related to stage member count.
- **Current evidence of support:** Plausible enforcement via turn-arrival tracking, but **not explicitly covered** by a generic area-occupation test.
- **Gap:** No generic area-occupation rule test file.
- **Impact:** High — affects all member placement abilities.

### 7. Q68 — "Cannot live" state definition
- **Date:** 2025.02.07
- **Rule:** A player who "cannot live" still places live cards face-down in set phase, but they are moved to discard during performance phase; no live start or cheer occurs.
- **Current evidence of support:** Code path exists but **no dedicated test** for `cannot_live` player flow.
- **Gap:** Missing from `qa_test_suite.rs` and test modules.
- **Impact:** Medium — affects cards that impose "cannot live".
