# Effect field architecture

Status: DONE — all shared fields consolidated onto `EffectFilter`.
Implemented at commit `febb6134` (blade_limit) + the follow-up consolidation.

## The design

**One source of truth per field.**

Every effect field lives on the shared `EffectFilter` struct (`engine/src/core/card.rs`).
`EffectKind` variants are now thin markers — each is just `{ filter: Option<Box<EffectFilter>> }`
— so the `filter()`/`filter_mut()` action-type dispatch still works, but no field is
duplicated on multiple variants.

```
EffectKind::GainResource { filter: Option<Box<EffectFilter>> }   // all fields here
EffectKind::ChangeState  { filter: Option<Box<EffectFilter>> }   // all fields here
…every variant is the same shape…
```

### What this eliminates

Before the change, a field like `sign` (used by `GainResource` + `MiscOp`) had to be
maintained in four places:

1. the enum field on **each** variant (2 copies),
2. `populate_from_json` in **each** action branch (2 copies),
3. `build_*` in the bytecode decoder (2 copies),
4. the `_any()` getter that pattern-matched both variants.

Adding a field to a new action type meant editing all four. Now:

- `EffectFilter` declares the field once.
- `populate_from_json`'s shared `filter()` closure reads it once.
- the bytecode decoder's `build_filter()` maps it once (generated by
  `cards/generate_effect_decoder.py`, which parses `card.rs` directly).
- getters are single-line `filter_*_getter!` calls.

### The pipeline

```
cards/abilities.json  (parser output)
        │
        ├─ JSON path   card.rs populate_from_json()
        │              build EffectKind::X { filter } — shared filter() closure
        │
        └─ bytecode    compile_abilities.py → abilities.bin
                       generate_effect_decoder.py → effect_decoder_gen.rs
                       build_filter(&EffectKindLocals) → EffectFilter (single place)
        │
        ▼
AbilityEffect { kind: EffectKind::X { filter }, … }
        │
        ▼
CardFilter (util.rs) — from_effect()/filter_subset() read every shared getter,
                       so no field can be silently dropped (D19 regression class).
```

### Getters

```rust
// before (N variant matches to keep in sync):
str_getter!(sign_any, [GainResource => sign, MiscOp => sign]);

// after (one shared location):
filter_str_getter!(sign_any, sign);   // reads EffectFilter.sign
```

The old variant-matching macros (`str_getter!`, `u32_getter!`, `bool_getter!`,
`vec_ref_getter!`, `setter!`, `copy_getter!`) were deleted.

## EffectFilter fields

142 fields: the original filter/targeting set (card_type, group, cost_limit,
heart_colors, source/target/destination, …) plus every field that used to live on
one or more `EffectKind` variants (blade_limit, need_heart_*, cost_reference,
target_member, sign, heart_type, choice_*, restriction_*, ability_gain, …).

## Regenerating the decoder

`effect_decoder_gen.rs` is generated — after changing `EffectFilter`/`EffectKind`
in `card.rs`, run:

```
python cards/generate_effect_decoder.py
```

The generator parses `card.rs`, so it stays in sync automatically.

## Fixing an ability: tests-first workflow

For every parser/engine fix (each entry in `cards/_bp07_ability_gaps_hand_analysis.md`):

1. **Write the Rust integration tests first** (`engine/tests/test_modules/*_test.rs`,
   registered in `mod.rs`), encoding exactly what the Japanese text says — not what
   the current parser emits. Cover **every edge case** the text implies (boundaries,
   negative cases, group/type filters, original-vs-current values, prompts vs
   auto-targeting, duration/cleanup).
2. **Steal the harness from tests of similar abilities** (same trigger, same
   action type): live-start gain tests, wait/change_state tests,
   place_energy_under_member tests, both-player effects, etc.
3. Run the new tests — they must FAIL against the current parser/engine output.
4. Fix `cards/ability_extraction/parser.py`, regenerate:
   `bash cards/regenerate.sh` (extract + compile + schema).
5. Fix the engine (`engine/src/...`) as needed.
6. `cargo test --test run_all` — new tests pass AND all existing tests stay green.
7. Commit. Then move to the next ability.
