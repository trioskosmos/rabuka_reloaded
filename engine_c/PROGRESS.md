# engine_c — C port of the Rabuka engine

> ## THE RULE
> Port `engine/src/...` into `engine_c/src/...` **file-by-file, faithfully**. Every
> branch, every state mutation. A function that compiles but only clears state and
> returns, or only calls `rb_resolver_clear_choice_state_and_resume`, is a **STUB**,
> not a port. Parity = the real Rust logic is reproduced.
>
> Gating suites that must stay green: `rb_engine_test` / `rb_engine_replay` /
> `rb_engine_ported`. The generated suite (`rb_engine_generated`) is a *worklist* and
> is allowed red.

## Status is GENERATED — do not hand-edit the "done" list
The single biggest source of lies here was humans/LLMs writing "✅ done" next to
files that were 3–30% ported. **Do not trust free-text progress claims.** Trust the
tools below; regenerate them and read the output.

```powershell
# 1. Substance + dependency tree (the one you want — see DEPENDENCY_AUDIT.md)
python tools/dep_audit.py --report DEPENDENCY_AUDIT.md

# 2. Scatter-shot placeholder markers (TODO / STUB / not yet / no-op / ...)
python tools/audit_placeholders.py

# 3. C-vs-Rust line ratio per file (catches "no C twin exists at all")
python size_audit.py
```

## Anti-patterns (do NOT do these — they look like progress, are not)
1. **A function that exists by name is NOT parity.** A handler whose body only does
   "clear the choice state + resume the queue" (or `return 0;`/`return 1;` with no real
   work) is a **stub**. Porting `choice.rs` by writing 30 `handle_*` functions that all
   just `rb_resolver_clear_choice_state_and_resume` produces code that *compiles* but is
   nowhere near the real logic. Parity = the actual branches/state mutations from the Rust
   function are reproduced.
2. **Never delete intermediate artifacts before the merged result is committed.** If you
   translate via per-function fragment files (`choice_frag_*.c`), you MUST assemble them
   into the real `.c`, **build + commit**, and only THEN (optionally) remove the fragments.
   Those `_frag_*.c` files are NOT in the `Makefile` SRC list and are not built — don't
   mistake a "complete" fragment for a complete port.
3. **One writer per file.** Subagents writing to the same `.c` concurrently corrupt it.
   Each subagent writes to its OWN uniquely-named fragment file; a single orchestrator
   concatenates/merges them into the one `.c` and commits.
4. **Do not invent a parallel architecture.** Translate the Rust methods onto the existing
   `rb_*` model (`GameState`, `RbChoice`, `queue.pending/deferred/resume_*`). Inventing a
   brand-new `RbAbilityResolver` with fields/helpers that don't exist produces un-mergeable
   fragments.
5. **Assemble/merge must read the ORIGINAL `.c` from `git show HEAD:...`, not the current
   working file** — otherwise you duplicate the header and the file balloons.

## How to verify a port is real (not just present)
Run `python tools/dep_audit.py --report DEPENDENCY_AUDIT.md` and confirm the function you
just wrote is classified `REAL` (not `STUB_NOOP`/`STUB_MARKER`) and that it is no longer in
the bottom-up work-order table. Cross-check with `size_audit.py` (C should be a meaningful
fraction of the Rust twin) and `audit_placeholders.py` (no TODO/STUB markers left).
