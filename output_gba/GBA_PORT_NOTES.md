# Rabuka GBA Port — Build & Debug Notes

Documentation for the Game Boy Advance port of Rabuka Reloaded, built with the
`agb` crate (the most mature Rust GBA SDK). Covers the toolchain, the sprite
text-rendering design, and the VRAM exhaustion crash that was root-caused and
fixed.

---

## 1. Status

- **Boots and plays the full flow**: mode select → deck select → RPS
  first-attacker → mulligan → full match.
- Verified stable in mGBA across many distinct screens (max observed ~204
  sprite groups, well under the 240 cap).
- Not yet tested on real hardware.

## 2. Layout

```
platforms/gba/
  Cargo.toml             # deps: agb 0.25, rabuka_engine (gba feature), portable-atomic
  .cargo/config.toml     # target thumbv4t-none-eabi, -Tgba.ld, arm7tdmi
  assets/pixelated.ttf   # small bitmap font baked at compile time (include_font!)
  src/lib.rs             # no_std, exports decks_baked / display / input
  src/decks_baked.rs     # baked deck card blobs (generated by tools/bake_deck_cards.py)
  src/display.rs         # object-text renderer (see "Text rendering" below)
  src/input.rs           # agb ButtonController wrapper -> platform_ui::PlatformUi
  src/bin/rabuka_gba.rs  # main: menus + full match loop mirroring PS1/DS
build_gba.bat            # bake decks -> cargo +nightly build -> agb-gbafix
output_gba/rabuka_gba.gba
```

Engine feature `gba` (in `engine/Cargo.toml`):
`no_std + bytecode_abilities + compact_cards + compact_card_data + compact_state`

## 3. Toolchain (this machine)

```bash
# From repo root:
./build_gba.bat
```

The script:
1. Runs `python tools/bake_deck_cards.py` → writes `engine/src/decks_cards_gen.rs`
   (keeps `load_two_decks()` in sync with the engine).
2. `cd platforms/gba && cargo +nightly build --release \
   -Z build-std=core,alloc -Zbuild-std-features=compiler-builtins-mem`
   (build-std is required because agb needs target-specific `core`/`alloc`).
3. `agb-gbafix <elf> -o output_gba/rabuka_gba.gba` (sets the GBA header, pads).

Notes:

- `portable-atomic` is pinned `=1.13.1` with
  `unsafe-assume-single-core`+`fallback`. agb requires
  `unsafe-assume-single-core`, which 1.14+ dropped support for on thumbv4t
  (ARMv4T has no atomics), so 1.14+ breaks the build.
- ARMv4T has no atomics → the engine's compat `Arc` is `alloc::rc::Rc` on this
  target (`use alloc::rc::Rc as Arc` in the binary).
- The ROM must be built from `platforms/gba/` for `.cargo/config.toml` (target +
  `gba.ld`) to apply.

## 4. Text rendering (the important part)

The GBA has no text layer. Two agb options:

| Approach | How it works | Why it was rejected |
|---|---|---|
| `RegularBackgroundTextRenderer` | allocates a fresh `DynamicTile16` in VRAM per glyph position | Exhausts the ~512-tile background budget in a few screens |
| `ObjectTextRenderer` | each `LetterGroup` becomes a sprite **object** that reuses shared font glyph tiles | Used by all real complete agb games (`the-dungeon-puzzlers-lament`, `object_text_render_advanced`) — chosen |

Design decisions in `display.rs`:

- **16×16 sprites** (`Size::S16x16`, default `LayoutSettings`, `max_group_width=16`).
  Each 16×16 sprite costs 4 VRAM tiles; the sprite allocator has **1024 tiles**.
  `S64x64` was tried and failed (4096 bytes per sprite can't be allocated).
- **240-group safety cap** (`layout.take(240)`): 240 groups × 4 tiles = 960 < 1024.
- GBA OAM holds **128 objects max**; `Object::show` silently drops objects
  beyond 128 (agb internal), so screens stay under the cap.

## 5. The crash: `dynamic.rs:107 AllocError` (fixed)

### Symptom

A panic at agb's internal `dynamic.rs:107:14` —
`should be able to allocate sprite buffer: AllocError` — freezing the game,
usually after the first big re-render (e.g. a 181→204-group screen after RPS).

### Root cause

`swap_buffers()` **re-allocated the whole screen of sprite objects every
frame**, even when the text had not changed (the engine re-renders the same
buffer in its input loops). Allocating the new screen's objects **while the
previous screen's objects were still in VRAM** produced a 2× transient that
overflowed the 32KB sprite VRAM (1024 tiles).

### Fix (in `display.rs::swap_buffers`)

1. **Early-return when the buffer is unchanged** (`self.buf == self.last`).
   The GBA keeps showing the last committed frame, so identical re-renders are
   skipped entirely.
2. **Drop an empty frame before allocating**
   (`self.text_objects.clear(); drop(self.gfx.frame()); let mut frame = self.gfx.frame();`).
   agb only moves the previous frame's sprite clones into a "previous" slot on
   the first `frame()`; a **second** `frame()` call is what actually drops and
   deallocates them. Calling it twice guarantees old buffers are free before
   the new screen is allocated.
3. **`.take(240)` cap** — bounds any single screen.

Result: no panic across many screens (max observed 204 groups), game progresses
through turns.

## 6. Testing with mGBA + debug logging

agb's panic handler logs to the mGBA debug console. To capture:

```bash
"/c/Program Files/mGBA/mGBA.exe" \
  -C debugger=1 -C logToFile=1 -C logFile="...\\output_gba\\log.txt" \
  -C logLevel=255 -l 255 output_gba/rabuka_gba.gba
```

- Config keys must be **unprefixed** (`debugger=1`, not `debugger.enable=1`).
- To log from ROM code, write the AGBA debug protocol directly (agb's `mgba`
  module is `pub(crate)`): handshake `0xC0DE` → `0x04FFF780`, read back
  `0x1DEA`, write bytes to `0x04FFF600`, set level at `0x04FFF700`.

## 7. Known limitations / next steps

- Screens are capped at 240 groups; very long lines can be truncated.
- Full match auto-play and manual play need longer soak testing.
- No audio, no card art (text-only like the DS/PS1 ports).
