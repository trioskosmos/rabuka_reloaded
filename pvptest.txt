PVP Flow Test Guide
====================

Fixes applied:
1. Deadlock fix: get_game_state and execute_action no longer hold
   rooms Mutex while calling resolve_game_state_arc (already fixed).
2. Stale actions cache: When PVP room game state is initialized,
   cached_actions is now invalidated so RPS/Mulligan/Main phase
   actions appear correctly.
3. rps_winner 0/1-based fix: pvp_player_can_act previously compared
   rps_winner (1=P1, 2=P2) directly to player_id (0=P1, 1=P2),
   causing ChooseFirstAttacker phase to give actions to the wrong
   player. Also fixed ChooseFirstAttacker/ChooseSecondAttacker
   handlers to respect rps_winner.
4. SSE: Game state updates pushed instantly via /api/events.

To test:

1. Open a NEW terminal (cmd.exe or PowerShell)

2. cd engine
   cd /d "C:\Users\trios\OneDrive\Documents\rabuka_reloaded\engine"

3. Build + start the server:
   cargo run --release --bin rabuka_engine web-server

   Wait for:
     "Game UI: http://127.0.0.1:8080"
     "LAN access: http://192.168.3.6:8080"

4. Open another terminal and run the full PVP flow:

   --- Create a PVP room ---
   $body = '{"mode":"pvp"}'
   $r = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/rooms/create" -Method Post -Body $body -ContentType "application/json"
   Write-Host "Room: $($r.room_id)  Token: $($r.session.session_id)"

   --- Check game state (room_not_ready) ---
   $h1 = @{"X-Room-Id"=$r.room_id; "X-Session-Token"=$r.session.session_id}
   $s = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/game-state" -Method Get -Headers $h1
   Write-Host "Room ready? $($s.room_not_ready)"

   --- Join as P2 ---
   $j = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/rooms/join" -Method Post -Body "{`"room_id`":`"$($r.room_id)`"}" -ContentType "application/json"
   Write-Host "P2 joined: $($j.session.player_id)"
   $h2 = @{"X-Room-Id"=$r.room_id; "X-Session-Token"=$j.session.session_id}

   --- P1 submits deck ---
   $d1 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/set_deck" -Method Post -Body "{`"player`":0,`"deck`":[`"PL!SP-sd2-001-P`",`"PL!SP-sd2-002-P`"],`"room_id`":`"$($r.room_id)`"}" -ContentType "application/json" -Headers $h1
   Write-Host "P1 deck: $($d1.room_init)"

   --- P2 submits deck (triggers game init) ---
   $d2 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/set_deck" -Method Post -Body "{`"player`":1,`"deck`":[`"PL!SP-sd2-001-P`",`"PL!SP-sd2-002-P`"],`"room_id`":`"$($r.room_id)`"}" -ContentType "application/json" -Headers $h2
   Write-Host "P2 deck - room_init: $($d2.room_init)"

   --- Get game state (should show RPS phase with 3 actions) ---
   $gs = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/game-state" -Method Get -Headers $h1 -TimeoutSec 10
   Write-Host "Phase: $($gs.phase)"
   Write-Host "Actions available: $($gs.legal_actions.Count)"
   Write-Host "Waiting for opponent: $($gs.waiting_for_opponent)"
   $gs.legal_actions | ForEach-Object { Write-Host "  Action: $($_.action_type) - $($_.description)" }

   --- P1 chooses Rock ---
   $exec1 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/execute-action" -Method Post -Headers $h1 -Body "{`"action_index`":0,`"action_type`":`"rock_choice`"}" -ContentType "application/json"
   Write-Host "After P1: $($exec1.phase)"

   --- P2 chooses Scissors (P1 wins) ---
   $exec2 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/execute-action" -Method Post -Headers $h2 -Body "{`"action_index`":2,`"action_type`":`"scissors_choice`"}" -ContentType "application/json"
   Write-Host "After P2: $($exec2.phase)"

   --- P1 should see ChooseFirstAttacker (not waiting) ---
   $s1 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/game-state" -Method Get -Headers $h1
   Write-Host "P1: Phase=$($s1.phase) Wait=$($s1.waiting_for_opponent) Actions=$($s1.legal_actions.Count)"
   $s1.legal_actions | ForEach-Object { Write-Host "  $($_.action_type)" }

   --- P2 should be waiting ---
   $s2 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/game-state" -Method Get -Headers $h2
   Write-Host "P2: Phase=$($s2.phase) Wait=$($s2.waiting_for_opponent)"

   --- P1 chooses Go First ---
   $exec3 = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/execute-action" -Method Post -Headers $h1 -Body "{`"action_index`":0,`"action_type`":`"choose_first_attacker`"}" -ContentType "application/json"
   Write-Host "After P1: $($exec3.phase)"

If the flow shows:
  - Phase: RockPaperScissors with 3 actions after deck submission
  - P1 can choose RPS, P2 can choose RPS
  - After both choose, correct player gets ChooseFirstAttacker
  - Mulligan → Main phase flows correctly
then all PVP fixes are working.
