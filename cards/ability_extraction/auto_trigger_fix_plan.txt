AUTO TRIGGER PARSER FIX PLAN
=============================
Date: 2026-06-19

PARSER FILE: cards/ability_extraction/parser.py
DATA FILE:   cards/abilities.json

PROBLEM OVERVIEW
----------------
56 jidou (自動) abilities in abilities.json. 12 have issues:

  - 5 abilities have NEITHER condition NOR trigger_condition
    → engine can't filter them at all: false positives on every scan
  - 7 abilities have trigger_condition but NO condition
    → scanning filters correctly, but resolution always passes (skips gate)
  - 38 abilities have both (working correctly)

Additionally, some condition types are mislabeled (e.g. stage→discard triggers
classified as card_count_condition instead of movement_condition).

ROOT CAUSES IN THE PARSER
--------------------------

CAUSE 1: _try_each_time() drops trigger when parse_condition returns None/custom
  File: parser.py, line 4547-4568
  When `parse_condition(trigger_text)` returns None or {"type":"custom"},
  the `trigger_condition` is never added to the effect.
  This affects patterns like:
    - "このメンバーが登場か、エリアを移動するたび" (appear_or_move)
    - "カードの効果によって自分のエネルギー置き場にエネルギーカードが置かれるたび" (energy_placed)
    - "自分の手札からカードが1枚以上控え室に置かれるたび" (hand_to_discard)
    - "自分のステージにいるメンバーのライブ成功時能力が解決するたび" (live_success)
  Fix: Add fallback trigger_condition that extracts generic fields.

CAUSE 2: _try_each_time() never populates effect.condition
  File: parser.py, line 4547-4568
  Even when trigger_condition IS parsed, the top-level `condition` field is
  never set. The engine checks `condition` during ability resolution.
  Fix: In post-processing, copy trigger_condition → condition when condition
  is absent.

CAUSE 3: _try_movement() doesn't handle "置かれた" (placed/discarded)
  File: parser.py, line 1107-1124
  The handler only matches "移動" (move). Stage→discard triggers use
  "置かれた" (placed) which is not a movement keyword. These fall through
  to generic handlers that produce card_count_condition or nothing.
  Fix: Add "置かれた" as a movement trigger pattern.

CAUSE 4: _try_card_count() catches stage→discard text as card_count_condition
  File: parser.py, line 677-862
  When "ステージから控え室に置かれた" text is parsed, the card count handler
  matches "枚以上" or similar count patterns and assigns card_count_condition.
  But the real trigger is about movement/discard, not card counting.
  Fix: Reorder handlers so movement patterns take priority over card_count
  when "置かれた" + location keywords are present.

CAUSE 5: _try_appearance() with center requirement yields wrong condition_type
  File: parser.py, line 1127-1192
  PL!HS-pb1-009-R has "センター" in text which is extracted as a position
  requirement. The appearance_condition is correct, but the fallthrough
  doesn't set it when "登場するたび" (appear each time) is present because
  the _try_each_time wrapper has already split the text.
  Fix: N/A — actually correct, the issue is in _try_each_time not propagating.

CAUSE 6: "自分のカードの効果によって" prefix prevents condition parsing
  Affects: PL!SP-bp5-004-R+ (move_or_energy), PL!SP-bp4-016-N (energy_each)
  The "自分のカードの効果によって" (by your card's effect) prefix is not
  recognized by any handler, so the condition falls through to generic.
  Fix: Add _try_self_effect pattern or integrate into _try_movement.

CAUSE 7: Complex yell conditions with sequential sub-actions lose trigger info
  Affects: PL!N-bp5-001-R+ (Ayumu), PL!S-bp2-004-R (Dia)
  These have sequential/conditional_on_result structures where sub-actions
  have their own conditions but the top-level trigger info is lost.
  Fix: Add extract_trigger_info_from_text() that runs post-parse on the
  full triggerless_text and fills in any missing condition/trigger_condition.
